# 版本、打包与自动更新

本文说明 Git 工作流、更新日志规则、自动打包与自动更新。功能与验收边界见 [原生接入说明](04-原生接入说明.md)。

## 仓库与提交

- 远程仓库：<https://github.com/yixin8875/mypaste>，默认分支 `main`。
- 每次改动使用独立提交，提交信息采用 `type(scope): 摘要`，例如 `feat(update): 接入自动更新`、`fix(store): 修复迁移列缺失`。
- 提交正文说明动机、影响范围与验证方式；不要提交 `node_modules/`、`dist/`、`src-tauri/target/`、`src-tauri/gen/`、签名私钥或任何真实剪贴板内容。
- 完成一项用户可见改动时，同步更新 `CHANGELOG.md` 的 `[Unreleased]`。发布时把条目移入具体版本，并写上发布日期（`YYYY-MM-DD`）。

## 版本号

以下四处必须一致：

1. `package.json` 的 `version`
2. `src-tauri/tauri.conf.json` 的 `version`
3. `src-tauri/Cargo.toml` 的 `version`
4. `src-tauri/Cargo.lock` 中 `mypaste` 包版本（由 `cargo build` 更新）

更新器按语义化版本比较，必须大于已发布版本才会提示更新。

## 自动打包

| 触发 | 工作流 | 产物 |
| --- | --- | --- |
| 推送到 `main` 或手动触发 | `.github/workflows/build.yml` | 运行前端与 Rust 测试，构建 NSIS 安装包并作为 Actions 产物保留 14 天 |
| 推送 `v*` 标签或手动触发 | `.github/workflows/release.yml` | 构建签名安装包、更新包与 `latest.json`，创建 GitHub Release |

`build.yml` 使用 `src-tauri/tauri.ci.conf.json` 关闭 updater 产物，因此普通提交打包不需要签名私钥。`release.yml` 必须配置签名密钥。

## 自动更新

- 更新端点：`https://github.com/yixin8875/mypaste/releases/latest/download/latest.json`
- 安装方式：Windows NSIS，`passive` 模式，安装器自行完成升级并重启。
- 设置 → 通用 → “检查更新”调用 `@tauri-apps/plugin-updater`；发现新版本后可下载安装并重启。
- 更新包必须通过 `tauri.conf.json` 中 `plugins.updater.pubkey` 对应的私钥签名；签名不符时拒绝安装。
- 自动更新只覆盖安装版；`npm run dev` 与浏览器演示不检查更新。
- Release 必须发布（非草稿），否则 `releases/latest` 不会返回它。

## 首次发布准备

1. 在本机生成密钥（已完成，私钥不在仓库）：

   ```bash
   npx tauri signer generate --ci -p "" -w "$USERPROFILE/.tauri/mypaste.key"
   ```

   私钥：`C:\Users\86176\.tauri\mypaste.key`；公钥已写入 `src-tauri/tauri.conf.json`。**私钥与密码一旦丢失，已安装客户端将无法再验证新版本。** 请离线备份。

2. 在 GitHub 仓库 `Settings → Secrets and variables → Actions` 添加：
   - `TAURI_SIGNING_PRIVATE_KEY`：私钥文件的完整内容（推荐直接粘贴内容）。
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：生成密钥时设置的密码；当前为空密码可不添加。
3. 确认仓库已启用 Actions，且 `Contents` 写权限允许工作流创建 Release。

## 发布流程

1. 更新 `CHANGELOG.md`，把 `[Unreleased]` 条目移入新版本小节。
2. 同步四处版本号。
3. 运行验证：

   ```bash
   npm test
   npm run test:rust
   npm run build
   npm run desktop:build -- --debug --no-bundle
   npm run test:native
   ```

4. 提交并推送：

   ```bash
   git add -A
   git commit -m "chore(release): v0.2.0"
   git push origin main
   ```

5. 打标签并推送，触发签名发布：

   ```bash
   git tag -a v0.2.0 -m "MyPaste v0.2.0"
   git push origin v0.2.0
   ```

6. 在 GitHub Release 页面确认安装包、`.sig` 与 `latest.json` 均已上传，Release 已发布。

## 验证自动更新

1. 安装旧版本（例如 0.1.0）的 NSIS 包。
2. 发布更高的新版本并等待 Release 完成。
3. 在旧版本设置 → 通用点击“检查更新”，确认显示新版本号与说明。
4. 点击“下载并安装”，确认下载进度、签名校验、安装与重启。
5. 若失败，检查 Release 是否已发布、`latest.json` 是否可匿名访问、私钥是否与公钥匹配。

自动更新的下载与安装无法在浏览器演示或自动化冒烟中验证，必须在真实安装版上人工验收。
