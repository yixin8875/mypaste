# 原生接入说明

本文记录实际落地的 Tauri 2 接入方式，以及它与 [技术设计基线](02-技术设计.md) 的差异。产品规则见 [产品需求](01-产品需求.md)，视觉规范见 [UI 设计规范](03-UI设计规范.md)。

## 范围

Windows 桌面版（Rust MSVC + WebView2）已接入：

- 系统剪贴板监听，采集文本、HTTP(S) 链接、位图与文件路径；
- SQLite 持久化、去重、收藏、集合、名称、备注、回收站；
- 托盘、关闭隐藏、单实例、全局快捷键；
- 暂停采集、保留策略、复制回系统剪贴板；
- 来源应用识别、按来源筛选与读取前排除；
- 图片缩略图、使用次数与最近使用排序；
- Windows 上尽力自动粘贴，失败时回退为“已复制，请手动 Ctrl+V”。

浏览器模式仍是可交互原型：使用合成数据、刷新重置，不连接系统剪贴板或本地数据库。**桌面连接失败时界面显示错误，不会回退成虚构记录。**

## 职责边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| Rust（`src-tauri/`） | 剪贴板读写与监听、SQLite、文件路径、托盘、快捷键、输入注入 | 界面渲染与业务文案 |
| React（`src/`） | 展示、搜索、编辑草稿、交互状态 | 直接访问系统剪贴板、数据库或文件 |
| 契约（`src/clipboard-service.ts`） | 类型化 `invoke` 与事件订阅 | 推断或伪造后端失败的结果 |

前端只通过 `@tauri-apps/api` 的 `invoke` 和事件通信；原生调用失败会作为错误展示，页面不会自行补数据。

## 命令与事件

命令注册于 `src-tauri/src/lib.rs` 的 `generate_handler!`，前端封装在 `src/clipboard-service.ts`。

| 命令 | 作用 |
| --- | --- |
| `get_snapshot` | 返回记录摘要列表、集合、设置、采集状态与数据目录 |
| `get_item` | 按数字 id 读取完整正文、备注等 |
| `search_items` | 后端全量搜索，返回匹配的 id |
| `update_item` | 修改名称、备注、收藏、集合、删除/恢复 |
| `purge_item` | 从回收站彻底删除 |
| `create_collection` | 新建集合 |
| `update_settings` | 修改暂停、保留策略、全局快捷键、排除应用 |
| `copy_item` | 按 id 把完整正文、文件列表或图片写回系统剪贴板 |
| `get_image` | 读取图片并返回 `data:image/png;base64,...` |
| `get_thumbnail` | 按需生成/读取最长边 320 px 的 PNG 缩略图，返回 data URL |
| `paste_item` | 快捷窗口中请求复制并尝试自动粘贴 |
| `open_link` | 仅允许 `http`/`https`，交给系统浏览器 |
| `hide_quick_window` | 关闭快捷窗口并使其会话失效 |

事件（均由 Rust 发往 `main` 窗口）：

- `history://changed`：记录或集合变化，前端重新读取快照；
- `capture://status`：暂停、监听或快捷键状态变化；
- `desktop://quick-open`：全局快捷键呼出快捷窗口。

前端先订阅事件、再读取快照，并用 generation/revision 丢弃过期响应。

## 数据

- 数据库：`history.sqlite3`，位于 Tauri 的应用本地数据目录；实际路径显示在设置“隐私”页。
- SQLite 开启 WAL 与 `foreign_keys`；`user_version` 为 4，高于当前版本会拒绝启动而不是猜测迁移。v1/v2/v3 库按顺序迁移到 v4。
- 表：`items`（含 `title`、`note`、`favorite`、`captured_at`、`deleted_at`、`png` BLOB、`file_size`、`file_modified`、`meta`、`source`、`thumb` BLOB、`last_used`、`use_count`）、`collections`、`members`、`settings`。
- `source` 为前台进程可执行文件名（不含 `.exe`，如 `chrome`）；无法读取时显示“未知来源”，不阻断采集。`last_used` 为最近一次复制时间，`use_count` 为成功写回剪贴板的次数，用于快捷窗口“最常使用”排序。
- `thumb` 为最长边 320 px 的 PNG 缩略图，单张最多 512 KiB；旧图片首次请求时生成并写回缓存。缩略图不通过快照传输，前端仅在行接近视口时调用 `get_thumbnail`。
- id 为 SQLite 自增整数，上限 `2^53-1`，可安全通过 JSON 传输。
- 列表只返回正文前 240 个字符（图片为空串）；完整内容按 id 读取，复制也按 id 执行，因此不会复制被截断的摘要。
- 图片以 PNG BLOB 存入数据库，单张 10 MiB、像素上限 2000 万；全部图片合计上限 500 MiB。
- 文件记录只保存路径与元数据快照，`content` 为换行分隔的绝对路径，不读取文件内容；`file_size` 为文件总字节、`file_modified` 为最近修改时间、`meta` 为逐项 JSON（`path/size/modifiedAt/isDir`）。单条最多 500 项或 1 MiB，重复路径会合并；文件夹不递归统计大小，元数据读取失败记为“大小未知”。
- 普通记录默认保留 500 条 / 30 天；收藏豁免条数与时间限制；回收站保留 7 天并占用空间。
- 去重按 `(kind, hash)`：重复内容恢复原记录并刷新时间，不丢失收藏、备注与集合。

### 测试隔离

调试构建允许用环境变量 `MYPASTE_DATA_DIR` 指定绝对路径作为数据目录；发布构建忽略该变量。原生冒烟脚本据此使用独立的临时目录，不触碰日常数据库。

## 剪贴板采集

- Windows 使用独立消息窗口注册 `AddClipboardFormatListener`，收到 `WM_CLIPBOARDUPDATE` 后读取剪贴板序列号，再读取文本或 DIB 位图。
- 采集线程与 UI 线程分离；停止监听时注销监听并退出消息循环。
- 暂停只停止写入新记录，不改变已有数据；状态持久化，重启后保留。
- 资源管理器复制的文件使用 `CF_HDROP`：读取 DROPFILES 中的路径列表，只对每个路径做一次 `metadata` 读取以记录大小、修改时间和是否文件夹，不打开文件内容；复制文件记录时同时写入 `CF_HDROP`（供资源管理器粘贴）和路径文本。
- 当剪贴板同时提供位图与文件列表时，若文件列表全部位于 `Temp`、`Tmp`、`INetCache` 等临时目录（浏览器和聊天软件复制图片的常见形态），优先保存位图并归入图片；文件列表指向用户文件路径时仍记为文件，避免把资源管理器的文件复制改成图片。
- 详情中显示总大小、最近修改和逐项元数据；总大小达到 1 GiB 时显示提示，说明粘贴时由目标应用实际复制，可能耗时并占用磁盘。
- 应用自己复制记录时记录序列号与内容哈希；监听线程据此抑制自写回，避免复制产生重复记录。
- 来源应用通过前台窗口 `GetForegroundWindow` 与 `QueryFullProcessImageNameW` 读取可执行文件名；系统不允许或不可用时显示“未知来源”，不阻断采集。
- 排除规则在**读取剪贴板内容之前**判断：若来源应用命中排除列表，只更新序列基线并跳过本次采集，不读取、解码或保存正文。名称比较忽略大小写、首尾空白与 `.exe` 后缀；来源识别失败时无法匹配，因此不能承诺拦截所有敏感内容。
- 图片在采集时若最长边超过 320 px，会缩放生成缩略图并随记录写入；小图直接复用原 PNG。
- 非 Windows 构建不启动监听，采集状态会显示为不可用。

## 自动粘贴边界

自动粘贴只在“由全局快捷键呼出快捷窗口、且目标窗口仍可靠”时尝试：

1. 请求开始时锁定 `QuickSession`，绑定呼出代次、目标 HWND 与目标进程 PID，并标记本次粘贴进行中。
2. 异步把记录写入系统剪贴板，拿到本次写入后的剪贴板序列号。
3. 发送输入前校验：会话代次/目标未变、粘贴仍被本请求持有、剪贴板序列仍是本次写入的序列。
4. 隐藏快捷窗口，再恢复目标窗口焦点；等待修饰键释放后，于发送 `Ctrl+V` 前再次校验剪贴板序列。
5. 任何一步不满足都**不发送输入**，返回 `manual_required`，界面提示“已复制，请手动 Ctrl+V”。

因此，粘贴过程中重新呼出快捷窗口、切换前台应用、目标进程退出或其他程序改写剪贴板，都不会把内容输入到错误位置。自动粘贴是尽力而为：Windows 可能拒绝恢复焦点，输入法、以管理员权限运行的目标程序等也会影响结果。

## 窗口、托盘与快捷键

- 主窗口关闭时拦截并隐藏，程序继续在托盘运行；托盘的“退出”才停止采集并结束进程。
- 托盘菜单提供打开、设置、暂停/继续与退出；左键单击打开主窗口。
- 全局快捷键默认 `Ctrl+Shift+V`，可在设置中修改；注册失败会显示冲突原因并回滚到原快捷键。
- 单实例：再次启动只唤出已运行窗口，不产生第二个采集进程。
- 快捷窗口按 `Esc` 关闭；由全局快捷键打开的窗口关闭后隐藏主窗口，在主界面打开的则返回主界面。
- 快捷窗口支持类型与集合筛选、“最近复制/最常使用”排序，并在本次运行内记住上次选择。Ctrl+Enter 若只完成复制但未发送输入，窗口保持打开并就地显示原因，不再直接关闭。

## 自动更新

- 使用 `tauri-plugin-updater` 与 `tauri-plugin-process`；capability 仅给 `main` 授予 `updater:default` 与 `process:allow-restart`。
- 更新端点：`https://github.com/yixin8875/mypaste/releases/latest/download/latest.json`；公钥写在 `tauri.conf.json` 的 `plugins.updater.pubkey`，私钥只在仓库外与本机 CI Secret 中。
- 设置 → 通用显示当前版本，可检查更新、显示更新说明与下载进度、下载安装并重启。Windows 使用 NSIS `passive` 模式，安装器负责升级与重启。
- 更新包与 `latest.json` 由 `v*` 标签触发的 GitHub Actions 生成；签名不匹配时更新器拒绝安装。
- 浏览器演示与 `npm run dev` 不检查更新；自动更新必须在安装版上人工验收。

## 与设计基线的差异

| 设计基线 | 实际实现 | 原因 |
| --- | --- | --- |
| 计划用 clipboard 插件监听 | 自建 Win32 消息窗口 | 官方 clipboard 插件只提供读写，不提供变更监听 |
| FTS5 全文检索 | `instr(lower(...))` 匹配 | 默认分词对中文支持有限，行为更需要可预测 |
| 图片存文件、数据库存路径 | PNG 直接存 SQLite BLOB | 单库备份与删除更简单，配额仍按字节控制 |
| 前端保存完整正文快照 | 快照只含 240 字符摘要 | 降低 IPC 体积，完整内容按需读取 |
| 复制与粘贴同一命令 | `copy_item` 与 `paste_item` 分开 | 只有快捷窗口场景才有可靠粘贴目标 |

## 验证方式与边界

自动化验证：

```bash
npm test
```

```bash
npm run test:rust
```

```bash
npm run desktop:build -- --debug --no-bundle
```

```bash
npm run test:native
```

- `npm test`：前端 15 项回归测试，覆盖原生失败不回退、写入失败提示、复制会话竞态、隐藏失败重试、订阅清理、完整正文搜索、文件路径展示、来源筛选与排除、缩略图按需加载、快捷窗口筛选/排序/未发送粘贴提示、设置页更新检查与安装、草稿保留与保存顺序。
- `npm run test:rust`：20 项 Rust 测试，覆盖自写回抑制、来源校验与排除名规范化、DTO 契约、会话代次与剪贴板序列、DIB 与 CF_HDROP 解码、v1/v2/v3 数据库迁移、文件元数据、使用次数、缩略图缓存、去重、搜索、保留策略、图片配额与持久化。
- `npm run test:native`：启动调试版，通过本机 WebView2 调试端口调用真实 IPC，验证隔离数据目录、首次无演示记录、设置/集合/排除规则持久化、非法参数拒绝、缩略图命令错误路径、重启后状态保留且未写入记录。结果写入 [native-smoke-result.json](native-smoke-result.json)。

未自动覆盖、需人工验收：

- 真实复制文本/链接/截图后是否出现记录，以及来源应用名是否正确；
- 在设置中排除一个真实应用后，从该应用复制内容是否完全不新增记录；解除排除后是否恢复；
- 复制截图，或从浏览器、聊天软件复制图片后，是否进入图片分类并显示缩略图；滚动长列表时是否逐步加载且不影响交互；
- 在资源管理器复制一个或多个文件/文件夹后，记录是否显示正确路径、大小与修改时间，复制该记录能否粘贴回资源管理器；总大小达到 1 GB 时是否出现提示；
- 全局快捷键在目标应用前台时能否呼出、修改与冲突提示；
- 快捷窗口中 Enter 复制、Ctrl+Enter 自动粘贴是否进入正确窗口；
- 已安装旧版本后，设置页能否发现新版本、下载安装并重启；签名错误时是否拒绝安装；
- 托盘菜单、关闭隐藏、单实例唤出；
- 高 DPI、多显示器与不同输入法下的粘贴表现。

冒烟脚本不会读写系统剪贴板内容，不能替代上述人工验收。
